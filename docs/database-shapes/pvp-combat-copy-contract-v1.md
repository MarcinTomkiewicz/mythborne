## 2. Design decision

### 2.1. Three separate copy layers

Do not merge these concerns in Angular.

```text
player.combat.common
```

Shared combat UI copy used by CombatHost / MinigameHost for live combat controls, meter, empty log, empty participants and workflow states.

```text
player.pvp.combat.sourcePresentation
```

PvP-specific combat source copy. It describes this combat as a hero-vs-hero estate assault. It should not replace the existing pre-combat PvP action decision copy.

```text
player.pvp.combat.context.participantEffectTemplates
```

DB-owned templates for participant effects such as Koszary, Forteca, blessing and curse. These templates are for DB/read-model composition. Frontend should render composed `participantEffects[]`, not invent text from raw keys or stat deltas.

### 2.2. No duplicated effect copy

There must be one source of effect copy:

```text
get_pvp_combat_copy(...).context.participantEffectTemplates
```

The same effect semantics are used by:

```text
live combat context
private PvP report combat context
public PvP report combat context
```

Report sections may have their own wrapper labels, but they must not define separate text variants for Koszary, Forteca, blessing or curse.

### 2.3. Public report visibility

Public PvP reports must not hide combat context just because it explains HP/stat values.

Public-safe context may show:

```text
hero display name
building kind
building level
effect kind
valueDisplay
display-ready rich text
```

Public-safe context must not show:

```text
UUIDs
raw metadata JSON
internal source rows
private debug payloads
raw formula context
```

### 5.3. Frontend usage

Use this only for PvP live/manual combat presentation.

Do not use it to replace existing pre-combat PvP decision copy from:

```text
get_pvp_action_copy(...).combatHandoff.header
get_pvp_action_copy(...).combatHandoff.decisionWindow
get_pvp_action_copy(...).combatHandoff.emptyCombatLog
```

PvP live/manual `CombatSourcePresentation` should be built from DB-owned copy:

```text
common = get_player_combat_common_copy(locale)
pvpCombat = get_pvp_combat_copy(locale)
```

Suggested composition:

```ts
CombatSourcePresentation = {
  header: pvpCombat.sourcePresentation.header,

  decision: existingPvpActionCopy.combatHandoff.decisionWindow,

  live: {
    ...common.live,
    title: pvpCombat.sourcePresentation.live.title,
    text: pvpCombat.sourcePresentation.live.text,
    helperText: pvpCombat.sourcePresentation.live.helperText
  },

  emptyLog: pvpCombat.sourcePresentation.emptyLog,

  emptyParticipants: common.emptyParticipants,

  workflow: pvpCombat.sourcePresentation.workflow
}
```

No Angular-local fallback strings.

## 6. `context.participantEffectTemplates`

Payload path:

```text
get_pvp_combat_copy(...).context.participantEffectTemplates
```

These are copy templates for DB/read-model composition.

Codex/frontend must not use raw effect keys, raw metadata, stat deltas, or these templates to locally invent player-facing text unless the user explicitly scopes a temporary frontend-only integration.

Target state: the DB/read model exposes composed effects:

```ts
interface PvpCombatParticipantEffect {
  key: string;
  participantRole: 'attacker' | 'defender';
  sourceKey: 'barracks' | 'fortress' | 'blessing' | 'curse';
  title: string;
  summaryPlain: string | null;
  summaryRichText: RichTextFragment[] | null;
  valueDisplay: string | null;
  tone: 'info' | 'warn' | 'danger' | 'success' | 'muted';

```


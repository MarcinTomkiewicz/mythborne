# UI-DASHBOARD-10 - Persistent State Source Matrix

Date: 2026-05-13

## Scope

This matrix defines which dashboard persistent-state widgets can be grounded in current production read models. It does not approve placeholder widgets, fake timers, local-only state, or speculative dashboard cards.

## Implementation Guidance

- UI-DASHBOARD-11 should render only states marked `Implement now`.
- Exploration activity state is conditional: the current production source for active exploration/step/challenge requires `difficultyKey`, and this matrix did not find a dashboard-safe active/current exploration difficulty source outside the page-local `ExplorationOverviewState` selection. UI-DASHBOARD-11 must not guess `difficultyKey`, hardcode a default, or reuse page-local exploration selection as a dashboard fallback. Active exploration/step/challenge rows remain blocked until a DB/read-model or accepted shared state exposes the active/current dashboard-safe difficulty, with stale clear on active hero/server/difficulty changes.
- Trials remaining is not difficulty-scoped. UI-DASHBOARD-11 may read the `trial` daily action counter directly through a read-only service method and must not derive the value from a selected exploration difficulty. The dashboard must not call `get_current_exploration_date`, because the player frontend may not have execute permission for that helper.
- Active combat effect state is not the same source as `HeroExplorationStateReadModel.activeEffect`: the dashboard-safe source is `get_hero_pending_combat_effect_state(p_hero_id)`, which does not require difficulty and can render a current buff/debuff state row.
- Missing or deferred states must not appear as empty placeholder cards.
- Exploration combat should be represented as an exploration handoff until a dedicated dashboard-safe combat discovery read model is scoped.
- Notifications already have topbar ownership; dashboard usage should wait for UI-DASHBOARD-14 to avoid duplicating the inbox.
- Dashboard widgets must clear on active hero/server changes and ignore stale async success/error paths.

## Reuse Notes

- Reused source patterns checked: `ExplorationOverviewState` request-token stale guard, `BuildingJobs.getHeroEstateRuntimeState(...)`, `GameReports.getActiveHeroUnreadCount()`, and `NotificationInbox.getPlayerUnreadCount()`.
- Checked but not approved as a dashboard source: `ExplorationLiveCombat`, because it requires an exploration combat session context and is not a standalone dashboard discovery read model.
- UI-DASHBOARD-11 source discovery found the Exploration page currently displays `Trials remaining` through `exploration-page.html` -> `ExplorationPageState.remainingTrialsLabel` -> `ExplorationOverviewState.remainingTrialsLabel` -> `HeroExplorationStateReadModel.remainingTrials`. That page path is difficulty-bound because it loads `HeroExplorations.getHeroExplorationState({ heroId, difficultyKey })`, but the underlying counter is `hero_daily_action_counters.action_kind = 'trial'` and is safe to read by active hero/server without difficulty.
- The `difficultyKey` source for active exploration/step/challenge is page-local `ExplorationOverviewState.selectedDifficultyKey`, initialized by `resolveSelectedDifficultyKey(...)` from the current page selection or the first active difficulty tier, so active exploration/step/challenge remain blocked for dashboard.
- No new production component, state class, helper, service, or mapper is added by this matrix.
